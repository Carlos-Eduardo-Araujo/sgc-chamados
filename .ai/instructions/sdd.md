# Regras SDD para o agente
1. Leia `docs/specification/specification.md` antes de alterar código.
2. Toda mudança funcional deve apontar RF, RNF ou RN correspondente.
3. Se código e especificação divergirem, não altere silenciosamente: proponha atualização explícita.
4. Crie/atualize testes antes de considerar a mudança concluída.
5. Não invente requisito inexistente apenas para ampliar escopo.
6. Preserve funcionalidades existentes que não conflitem com a especificação.
